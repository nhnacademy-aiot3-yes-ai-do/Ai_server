> AI 응답 하나를 만드는 데서 끝내지 않고, 데이터 계약·생성·저장·알림 전달의 경계를 연결한 경험을 남긴다.

## 이 문서의 목적

MushMush 팀 프로젝트에서 김민서가 담당한 **Vision 결과 연동과 일일 피드백**의 배경, 구현 판단, 트러블슈팅, 검증 근거와 한계를 정리한다. 나중에 포트폴리오·이력서·자기소개서·면접을 준비할 때 실제 사건을 복원하기 위한 개인 경험 아카이브다.

이 폴더는 AI 서버 저장소 안에서 독립적으로 읽을 수 있다. 프로젝트 전체 운영 매뉴얼이나 모든 AI 기능의 개인 구현 증명서는 아니다.

## 확인 등급 읽는 법

- **코드 확인:** 기준 revision에서 해당 동작·선언이 존재한다. 실행·배포 성공까지 뜻하지 않는다.
- **기록 확인:** 커밋·보고서·테스트 시나리오 등 기록이 있다. 테스트 소스와 통과 기록을 구분한다.
- **대화 증거:** 사용자가 제공한 로그·이미지·설명으로 당시 관찰을 확인한다. 원자료가 없어 원인까지 확정하지 못할 수 있다.
- **판단/회고:** 확인한 근거에서 도출한 해석이다. 직접 측정한 성과와 다르다.
- **제안/미확인:** 개선 방향 또는 추가 증거가 필요한 항목이다. 완료 사실로 사용하지 않는다.
